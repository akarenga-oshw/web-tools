Getting into boot mode, and what tends to go wrong

USB boot mode: release reset with the MD pin held low, then connect USB. The part enumerates as 045B:0261 "RA USB Boot". Baud rate and parity mean nothing over CDC, so there is no synchronisation sequence to do — the tool starts at Inquiry.

SCI boot mode: release reset with MD low, then at 9600 8N1 send 0x00 twice for an ACK of 0x00, then 0x55 for the boot code 0xC3. If nothing answers, the tool retries the synchronisation with ODD parity and switches to NONE once 0xC3 arrives. That behaviour is documented nowhere but has been reported on RA2 parts; RA4M1 normally works with NONE throughout.

Windows: Web Serial cannot see the port unless RA USB Boot is bound to usbser.sys. Check that it appears as a COM port in Device Manager first. Renesas Flash Programmer may have claimed it with a different driver.

ID authentication: on a part that carries an ID code, Inquiry answers with a flow error (0xC3). The tool then tries to authenticate with FF×16, which is what an unprotected part accepts.
